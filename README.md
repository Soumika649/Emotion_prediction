# Emotion Classifier 🎭

A text emotion classification system that predicts one of six emotions (**sadness, joy, love, anger, fear, surprise**) from raw text, built on the [dair-ai/emotion](https://huggingface.co/datasets/dair-ai/emotion) dataset and served via a FastAPI backend.

The project compares four sequence-model architectures (SimpleRNN, LSTM, GRU, BiGRU) to justify the final model choice, then deploys the winning model behind a production-style REST API.

## Problem

Understanding the emotional tone of text has applications in customer feedback analysis, mental health chatbots, content moderation, and social media monitoring. This project frames it as a 6-class supervised text classification problem.

## Dataset

- **Source:** [dair-ai/emotion](https://huggingface.co/datasets/dair-ai/emotion) (~20k labeled English Twitter-style sentences)
- **Classes:** sadness, joy, love, anger, fear, surprise
- **Class imbalance:** handled via `sklearn.utils.class_weight.compute_class_weight`

## Approach

1. **Preprocessing:** lowercasing, apostrophe stripping, punctuation/special-char removal, whitespace normalization
2. **Tokenization:** Keras `Tokenizer` (vocab size 1000) + padding/truncation to a fixed sequence length of 50
3. **Modeling:** four architectures trained and compared under identical conditions (`class_weight`, `EarlyStopping(patience=3, restore_best_weights=True)`, 20 epochs, batch size 32)
4. **Selection:** best-performing model exported (`.keras` + `tokenizer.pkl`) and served via FastAPI

## Model Comparison

| Model | Embedding Dim | Val. Accuracy | Val. Loss |
|-------|---------------|----------------|-----------|
| SimpleRNN | 128 | 27.2% | 1.769 |
| LSTM | 128 | 13.8% | 1.810 |
| GRU | 128 | 13.8% | 1.772 |
| **BiGRU (final)** | **300** | **86.4%** | **0.350** |

> The plain recurrent models underperform sharply here, most likely due to `EarlyStopping` restoring weights from a very early epoch before those networks converged, combined with the smaller 128-dim embedding. The BiGRU's bidirectional context and larger embedding space closed that gap. Re-running with higher patience and logging per-epoch curves (see `evaluate.py`) is a good next step to confirm this rather than assume it.

Full per-class precision/recall/F1 and a confusion matrix are generated by `evaluate.py` (see below) — add the output table here once you run it.

## Architecture

```
                ┌─────────────┐
   User text →  │  FastAPI    │ → preprocess_text() → Tokenizer → pad_sequences
                │  /predict   │
                └──────┬──────┘
                       ▼
              BiGRU_Modle.keras
                       │
                       ▼
        {predicted_emotion, confidence, all_probabilities}
```

## API

| Method | Endpoint  | Description |
|--------|-----------|--------------|
| GET    | `/`       | Web UI |
| GET    | `/health` | Health check + model-loaded status |
| POST   | `/predict`| Predict emotion for a given text |

**Example request:**

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "I cant believe how happy I am right now"}'
```

**Example response:**

```json
{
  "text": "I cant believe how happy I am right now",
  "predicted_emotion": "joy",
  "confidence": 0.94,
  "all_probabilites": {
    "sadness": 0.01, "joy": 0.94, "love": 0.02,
    "anger": 0.01, "fear": 0.01, "surprise": 0.01
  }
}
```

## Running Locally

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
# Open http://localhost:8000
```

## Running with Docker

```bash
docker build -t emotion-classifier .
docker run -p 8000:8000 emotion-classifier
```

